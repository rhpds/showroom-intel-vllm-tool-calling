= Module 2: Deploy vLLM with Tool Calling

_Estimated time: 15 minutes_

In this module you will clone the quickstart repository, deploy vLLM with tool calling enabled, and verify the model is serving. You have two paths: deploy Granite 3.2-8B on-cluster, or connect to Qwen3-14B via Model as a Service (MaaS).

== Clone the Repository

Clone the quickstart repository into your home directory:

[source,bash,role="execute",subs="attributes+"]
----
cd ~ && git clone {quickstart_repo}
----

Examine the Kustomize overlay structure:

[source,bash,role="execute"]
----
ls ~/vllm-tool-calling/
----

Each model has its own overlay directory with device-specific configurations (CPU or GPU). The overlays set the model name, resource limits, and the `--enable-auto-tool-choice` flag that activates function calling.

== Option A: Deploy Granite 3.2-8B On-Cluster

Apply the Kustomize overlay for Granite 3.2-8B on CPU:

[source,bash,role="execute",subs="attributes+"]
----
oc apply -n {project_name} -k ~/vllm-tool-calling/granite-3.2-8b/cpu
----

Monitor the deployment until the pod is running:

[source,bash,role="execute",subs="attributes+"]
----
oc get pods -n {project_name} -w
----

Press `Ctrl+C` once the vLLM pod reaches `Running` status. The model download may take 3-5 minutes depending on network speed.

Set the model endpoint for the rest of the lab:

[source,bash,role="execute",subs="attributes+"]
----
export MODEL_URL=$(oc get route vllm-tool-calling -n {project_name} -o jsonpath='https://\{.spec.host\}/v1')
export MODEL_NAME="granite-3.2-8b"
echo "Model URL: $\{MODEL_URL\}"
----

== Option B: Use Model as a Service (MaaS)

If you prefer to skip the on-cluster deployment and use a pre-hosted model, set these variables instead:

[source,bash,role="execute",subs="attributes+"]
----
export MODEL_URL={maas_api_url}
export MODEL_NAME={maas_model}
echo "Model URL: $\{MODEL_URL\}"
echo "Model Name: $\{MODEL_NAME\}"
----

The MaaS endpoint serves {maas_model}, which has strong tool calling capabilities. No deployment is needed -- the endpoint is ready immediately.

== Verify the Model Is Serving

Regardless of which option you chose, verify the model is responding by listing available models:

[source,bash,role="execute"]
----
curl -s $\{MODEL_URL\}/models | python3 -m json.tool
----

You should see a JSON response listing your model as available. If you used Option A, look for `granite-3.2-8b` in the response. For Option B, look for `{maas_model}`.

== Send a Basic Chat Completion

Test with a simple chat completion (no tools yet) to confirm the model is working:

[source,bash,role="execute"]
----
curl -s $\{MODEL_URL\}/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$\{MODEL_NAME\}"'",
    "messages": [
      {"role": "user", "content": "What is function calling in AI?"}
    ],
    "max_tokens": 150
  }' | python3 -m json.tool
----

You should receive a natural language response explaining function calling. This confirms the model endpoint is healthy and ready for tool calling in the next module.
