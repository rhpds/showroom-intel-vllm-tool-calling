= Module 3: Your First Tool Call

_Estimated time: 20 minutes_

In this module you will learn the OpenAI-compatible tools API format, send a request with a tool definition, parse the model's tool call response, execute a mock tool, and return the result to get a final answer. This is the complete tool calling loop, step by step.

== How Tool Calling Works

The tool calling flow has four steps:

1. *Define tools* -- You describe available functions using JSON Schema in your API request
2. *Model requests a tool call* -- Instead of answering directly, the model returns a `tool_calls` array with the function name and arguments
3. *You execute the tool* -- Your application runs the function and collects the result
4. *Return the result* -- You send the tool result back to the model, which generates the final answer

The model never executes code. It only decides *which* function to call and *what arguments* to pass.

== Step 1: Define a Tool

Create a JSON file with a tool definition for a weather lookup function:

[source,bash,role="execute"]
----
cat > ~/get_weather_request.json << 'ENDJSON'
{
  "model": "MODEL_PLACEHOLDER",
  "messages": [
    {"role": "user", "content": "What is the weather like in Boston today?"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "Get the current weather for a given location",
        "parameters": {
          "type": "object",
          "properties": {
            "location": {
              "type": "string",
              "description": "The city and state, e.g. Boston, MA"
            },
            "unit": {
              "type": "string",
              "enum": ["celsius", "fahrenheit"],
              "description": "Temperature unit"
            }
          },
          "required": ["location"]
        }
      }
    }
  ],
  "tool_choice": "auto"
}
ENDJSON
----

Now substitute your actual model name into the request:

[source,bash,role="execute"]
----
sed -i "s/MODEL_PLACEHOLDER/$\{MODEL_NAME\}/" ~/get_weather_request.json
cat ~/get_weather_request.json | python3 -m json.tool
----

Key fields in the tool definition:

* `name` -- The function identifier the model will reference
* `description` -- Helps the model decide when to use this tool
* `parameters` -- JSON Schema describing the function's arguments
* `tool_choice: "auto"` -- The model decides whether to call a tool or respond directly

== Step 2: Send the Request

Send the request to the model endpoint:

[source,bash,role="execute"]
----
curl -s $\{MODEL_URL\}/chat/completions \
  -H "Content-Type: application/json" \
  -d @~/get_weather_request.json > ~/tool_response.json
cat ~/tool_response.json | python3 -m json.tool
----

Examine the response. Instead of a regular `content` message, you should see a `tool_calls` array in the assistant's message. The model is requesting that you call `get_weather` with `location: "Boston, MA"`.

== Step 3: Parse the Tool Call

Extract the tool call details from the response:

[source,bash,role="execute"]
----
TOOL_CALL_ID=$(python3 -c "
import json
r = json.load(open('$\{HOME\}/tool_response.json'))
tc = r['choices'][0]['message']['tool_calls'][0]
print(tc['id'])
")
FUNCTION_NAME=$(python3 -c "
import json
r = json.load(open('$\{HOME\}/tool_response.json'))
tc = r['choices'][0]['message']['tool_calls'][0]
print(tc['function']['name'])
")
FUNCTION_ARGS=$(python3 -c "
import json
r = json.load(open('$\{HOME\}/tool_response.json'))
tc = r['choices'][0]['message']['tool_calls'][0]
print(tc['function']['arguments'])
")
echo "Tool Call ID: $\{TOOL_CALL_ID\}"
echo "Function: $\{FUNCTION_NAME\}"
echo "Arguments: $\{FUNCTION_ARGS\}"
----

The model has decided to call `get_weather` and provided structured arguments. In a real application, you would dispatch this to an actual weather API.

== Step 4: Execute the Tool (Mock)

Simulate executing the weather function. In production, this would be a real API call:

[source,bash,role="execute"]
----
TOOL_RESULT='{"temperature": 72, "unit": "fahrenheit", "condition": "partly cloudy", "humidity": 65}'
echo "Mock tool result: $\{TOOL_RESULT\}"
----

== Step 5: Return the Result to the Model

Now send the complete conversation back to the model -- including the original message, the assistant's tool call, and the tool result:

[source,bash,role="execute"]
----
ASSISTANT_MSG=$(python3 -c "
import json
r = json.load(open('$\{HOME\}/tool_response.json'))
print(json.dumps(r['choices'][0]['message']))
")

curl -s $\{MODEL_URL\}/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$\{MODEL_NAME\}"'",
    "messages": [
      {"role": "user", "content": "What is the weather like in Boston today?"},
      '"$\{ASSISTANT_MSG\}"',
      {
        "role": "tool",
        "tool_call_id": "'"$\{TOOL_CALL_ID\}"'",
        "content": "'"$\{TOOL_RESULT\}"'"
      }
    ]
  }' | python3 -m json.tool
----

The model now generates a natural language response incorporating the weather data. Instead of guessing, it uses the actual data you provided: 72 degrees, partly cloudy, 65% humidity.

== Understanding the Message Flow

Here is the complete message sequence you just executed:

[cols="1,1,3"]
|===
| Step | Role | Content

| 1 | `user` | "What is the weather like in Boston today?"
| 2 | `assistant` | `tool_calls: [{name: "get_weather", arguments: {location: "Boston, MA"}}]`
| 3 | `tool` | `{temperature: 72, condition: "partly cloudy"}`
| 4 | `assistant` | "The weather in Boston is currently 72F and partly cloudy..."
|===

This four-step pattern is the foundation of every tool calling implementation, whether you use `curl`, Python, or an agent framework.
