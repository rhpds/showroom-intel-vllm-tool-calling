= Module 5: Advanced Tool Calling Patterns

_Estimated time: 10 minutes_

In this module you will explore multi-turn tool calling, parallel tool calls, error handling, and learn when tool calling is not the right approach.

== Multi-Turn Tool Calling

Some questions require chaining multiple tools. For example: "What is the weather where Alice Johnson works?" requires looking up the employee first, then checking the weather for their location.

Run a multi-turn example:

[source,bash,role="execute"]
----
cat > ~/multi_turn.py << 'PYEOF'
import json, os
from openai import OpenAI

client = OpenAI(base_url=os.environ["MODEL_URL"], api_key="not-needed")
MODEL = os.environ["MODEL_NAME"]

tools = [
    {"type": "function", "function": {
        "name": "lookup_employee",
        "description": "Look up an employee and return their department, title, and office location",
        "parameters": {"type": "object", "properties": {
            "name": {"type": "string", "description": "Employee full name"}
        }, "required": ["name"]}
    }},
    {"type": "function", "function": {
        "name": "get_weather",
        "description": "Get the current weather for a location",
        "parameters": {"type": "object", "properties": {
            "location": {"type": "string", "description": "City and state"}
        }, "required": ["location"]}
    }},
]

def lookup_employee(name):
    employees = {
        "Alice Johnson": {"department": "Engineering", "title": "Staff Engineer", "office": "Boston, MA"},
        "Bob Smith": {"department": "Sales", "title": "Account Executive", "office": "San Francisco, CA"},
    }
    return employees.get(name, {"error": "not found"})

def get_weather(location):
    data = {"Boston, MA": {"temp": 72, "condition": "sunny"}, "San Francisco, CA": {"temp": 58, "condition": "foggy"}}
    return data.get(location, {"temp": 65, "condition": "unknown"})

FUNCTIONS = {"lookup_employee": lookup_employee, "get_weather": get_weather}

messages = [{"role": "user", "content": "What is the weather like where Alice Johnson works?"}]
print("User: What is the weather like where Alice Johnson works?\n")

turn = 0
while turn < 5:
    response = client.chat.completions.create(model=MODEL, messages=messages, tools=tools, tool_choice="auto")
    msg = response.choices[0].message
    if not msg.tool_calls:
        print(f"Assistant: {msg.content}")
        break
    messages.append(msg)
    for tc in msg.tool_calls:
        args = json.loads(tc.function.arguments)
        print(f"  Turn {turn + 1}: {tc.function.name}({args})")
        result = FUNCTIONS[tc.function.name](**args)
        print(f"           -> {json.dumps(result)}")
        messages.append({"role": "tool", "tool_call_id": tc.id, "content": json.dumps(result)})
    turn += 1
PYEOF
python3 ~/multi_turn.py
----

The model should first call `lookup_employee` to find Alice's office location, then call `get_weather` with that location. This chaining behavior emerges naturally -- you do not need to program the sequence.

== Parallel Tool Calls

Some models can request multiple tool calls in a single response. For example, if asked "What is the weather in Boston and San Francisco?", the model may return two `get_weather` calls at once.

Test parallel tool calling:

[source,bash,role="execute"]
----
curl -s $\{MODEL_URL\}/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "'"$\{MODEL_NAME\}"'",
    "messages": [
      {"role": "user", "content": "Compare the weather in Boston and San Francisco right now."}
    ],
    "tools": [
      {"type": "function", "function": {
        "name": "get_weather",
        "description": "Get the current weather for a location",
        "parameters": {"type": "object", "properties": {
          "location": {"type": "string", "description": "City and state"}
        }, "required": ["location"]}
      }}
    ]
  }' | python3 -c "
import json, sys
r = json.load(sys.stdin)
tcs = r['choices'][0]['message'].get('tool_calls', [])
print(f'Number of tool calls: {len(tcs)}')
for tc in tcs:
    print(f'  {tc[\"function\"][\"name\"]}({tc[\"function\"][\"arguments\"]})')
"
----

If you see two tool calls, the model is requesting parallel execution. Your application should execute both tools and return both results before the next model call. If the model returns only one call, it will chain them sequentially -- both approaches work.

== Error Handling

Tools fail in production. APIs time out, databases go down, and queries return empty results. The model can handle errors gracefully if you return structured error information:

[source,bash,role="execute"]
----
cat > ~/error_handling.py << 'PYEOF'
import json, os
from openai import OpenAI

client = OpenAI(base_url=os.environ["MODEL_URL"], api_key="not-needed")
MODEL = os.environ["MODEL_NAME"]

tools = [{"type": "function", "function": {
    "name": "check_inventory",
    "description": "Check inventory levels for a product",
    "parameters": {"type": "object", "properties": {
        "product": {"type": "string"}
    }, "required": ["product"]}
}}]

messages = [{"role": "user", "content": "How many widget-xyz units do we have?"}]
response = client.chat.completions.create(model=MODEL, messages=messages, tools=tools, tool_choice="auto")
msg = response.choices[0].message

if msg.tool_calls:
    tc = msg.tool_calls[0]
    print(f"Tool call: {tc.function.name}({tc.function.arguments})")
    error_result = json.dumps({"error": "product_not_found", "message": "No product matching 'widget-xyz' exists in the catalog"})
    print(f"Returning error: {error_result}\n")
    messages.append(msg)
    messages.append({"role": "tool", "tool_call_id": tc.id, "content": error_result})
    final = client.chat.completions.create(model=MODEL, messages=messages)
    print(f"Assistant: {final.choices[0].message.content}")
PYEOF
python3 ~/error_handling.py
----

The model should acknowledge the error and respond appropriately -- telling the user the product was not found rather than hallucinating an inventory count.

== When NOT to Use Tool Calling

Tool calling adds latency and complexity. Avoid it when:

[cols="1,3"]
|===
| Scenario | Why Tools Are Wrong

| *General knowledge questions*
| "What is Python?" -- the model already knows this. A tool adds a round trip for no benefit.

| *Creative writing*
| "Write me a poem about clouds" -- no external data is needed.

| *Simple classification*
| "Is this email spam?" -- the model can classify directly from the input text.

| *Summarization*
| "Summarize this document" -- the content is already in the prompt.
|===

Use tool calling when the model needs *live data*, *private data*, or *precise computation* that it cannot produce from its training alone.
